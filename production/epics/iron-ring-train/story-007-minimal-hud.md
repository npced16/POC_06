## Implementation Notes

- UI Toolkit selected after checking `docs/engine-reference/unity/modules/ui.md` (Unity 6.3 runtime recommendation, dynamic elements, DropdownField and flex layout). UXML/USS keeps layout separate; a ScrollView supports a data-driven hub count.
- `HudController` takes all seven contract interfaces through its constructor. Initial snapshots are read once; subsequent system values change only in event callbacks. The HUD never calls inventory mutations, prosperity mutations, movement, recruitment or encounter resolution.
- Explicit player orders use `IHabitatSystem.TryPlace` and `IFacilityBuilder.TryBuild`; systems retain validation and mutation ownership. Selection and command feedback are local presentation state.
- `HudDocument.Bind` receives slot indices and facility IDs from the composition root. Demo values live in `Assets/UI/Story007/DemoData.json`; five hubs demonstrate expansion beyond four without a code change. They do not alter gameplay balance defaults.
- Real systems are being built in parallel; the authorized demo consumes scene-local scripted fakes. No shared bootstrap, contract, build settings or unrelated scene was modified.
- `docs/README.md` was absent. Followed this story and the project `/dev-story` minimal workflow; no test source was written per AGENTS.md. Scene and PanelSettings creation uses Unity Editor APIs and preserves existing assets on later builds.

- UI 구현 방식(UI Toolkit 또는 UGUI)은 Unity 6.3 참조 문서(`docs/engine-reference/unity/`)에서 확인하고, 선택 이유를 스토리 완료 시 기록한다.
- 아트 방향은 황동과 증기 톤이다. 이 스토리에서는 읽기 쉬움이 우선이고 장식은 나중으로 미룬다.
